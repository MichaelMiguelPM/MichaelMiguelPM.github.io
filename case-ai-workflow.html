The Challenge

Accelerate or die: a thin engineering team

I owned two roadmap bets — Project Room v2, a full redesign of Brightidea's collaboration space, and a self-serve Hackathon Free Trial that turns an anonymous visitor into a paying customer. Both had to move fast against limited engineering capacity, so I deliberately stress-tested an AI-driven delivery process using Claude to do work that used to wait on design reviews, designers, front-end devs, or other cross-functional peers.

Limited engineering capacity

Two roadmap bets, not enough dev hours to build them the traditional way.

Design & front-end bottleneck

Prototype and UI work stalled waiting on designer and FE availability.

A heavy process to build

The classic research → design review → prototype → PRD → dev hand-off was too slow for the pace we wanted.

A process worth proving

If AI could compress delivery, it would change how the whole product team ships.

How I Work

One loop: Chat → Design → Code → Ship

Requirements stay deliberately loose up front — the transcript and the prototype become the spec. Feedback from each review feeds straight back into the loop.

1 Claude Chat

Research, synthesize meeting transcripts, draft the backlog, debug, and learn new tools on the fly.

2 Claude Design

Turn requirements into a clickable prototype the team can react to, edit, and review live.

3 Claude Code

Build the prototype into production front-end and back-end, gated behind feature toggles.

4 Cowork + MCP

Wire Claude into Slack, local dev, GitHub, and Brightidea's own MCP to run the loop end to end.

Proof · Project Room v2

From a Claude prototype to shipped UI

1 Prototype in Claude Design

Built a clickable Project Room homepage, iterated it with stakeholders in a live review, and shared individual files for each team member to ideate on.

2 Hand off to Claude Code

Our front-end dev took the same design file into Claude Code. Once the flows stuck, net-new pages came together in a fraction of the usual time.

3 Ship behind toggles

Homepage, project-level chat, history, unified Hackathon/Enterprise templates and dark mode — roughly 30 story points, every piece gated for enterprise safety.

Proof · Hackathon Free Trial

I pushed the entire Hackathon Free Trial setup through my own local dev — no engineers, Claude-enabled. In about two days I had the full path working end to end, on a branch pushed to GitHub.

New product type

New self-serve signup form

A landing page wired to a HubSpot form that captures the lead.

Template resolution

Per-template design folders so the create flow returns the right resources.

Verified end to end

Web page → signup → HubSpot → domain/password → system creation → live hackathon.

Solve Problems

Using AI to get unstuck

Local dev, debugged with Claude

Missing Composer deps, stale nginx routing, an un-compiled JS bundle, an expiring dev cert — Claude diagnosed and fixed the environment gaps so the demo ran.

Meetings become the spec

I narrate decisions on a call, then have Claude pull the transcript, extract action items, and draft the Jira tickets and PRD — no separate write-up.

Backlog audits on demand

Claude reads the Slack and Jira trail and surfaces what's done, blocked, or missing, so nothing quietly falls through the cracks.

CI as a safety net

Our pod added CI checks on every PR; when AI writes a feature, I hand the failure straight back to Claude to fix and re-run.

Learn

New territory in days, not weeks

This work pushed me well outside a typical PM lane — into HubSpot internals, Stripe products, local Docker builds, GitHub workflows, and MCP. The point was never to replace engineers or designers; it was to remove the wait, arrive at every conversation with something real, and keep the loop moving.

New tooling on demand

Rebuilt my HubSpot knowledge and stood up the signup form and custom properties without a specialist.

Full-stack fluency

Got comfortable in the codebase, local environment, and GitHub — enough to open real, review-ready PRs.

Wiring Claude into the stack

Connected Claude to local dev, GitHub, and Brightidea's MCP so one AI loop spans design, code, and QA.

Outcomes

What the AI workflow changed

  • Compressed delivery from weeks to days. A self-serve trial that once implied a multi-engineer, multi-week effort came together solo in about two days.
  • Shipped a full Project Room redesign (v2) into the release for Enterprise and Hackathon, built through a Claude Design → Claude Code pipeline without a designer.
  • Redefined an AI-empowered PM role — a single PM prototyping, building, and debugging, not just writing specs and waiting.
  • Turned an experiment into a repeatable team process that can move the product team at ~5× pace.
  • Biggest lesson: keep requirements loose early and let the prototype and transcript be the spec — speed comes from iterating in the tool, not from a heavier plan.
