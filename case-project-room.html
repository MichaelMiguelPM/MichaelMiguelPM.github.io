The Challenge

Create a true team collaboration space

A new enterprise Project Room showed only a name, one member, and an empty description — hard-coded and lifeless. The core question: how do we make a room useful, social, and self-explanatory the moment it exists?

Bare & uninformative rooms

A new room showed only a name, one member, and an empty description — no way to intuit what it was for.

No useful objects

Users had no idea what could be done inside, hunting through a small icon to create a memo, task, or whiteboard.

No initiative rooms

No templates per app, so the Project Room was never leveraged at the Initiative level.

No team collaboration

No roles, no sense of who was invited or when, and no way to communicate about the project.

No activity or history

No record of activity or recent work, so users couldn't tell what was happening on their projects.

Research

Same problems, converging evidence

The same "no context / too empty / what do I even do" complaint surfaced independently across the Project Room audit — a real problem, not a cosmetic one.

"Empty Dance Floor" room UX

Gina Romero (CS Rep): "No billboard, no description, or pre-loaded objects on first touch — so clients bypassed or did not adopt."

Project Summary banner + context
"What do I do or create?"

Veronika Vacek (CS Rep): "When a new Project Room is created there is no main CTA or helpful onboarding, leaving my clients lost."

Default-template objects + clear CTAs
Team-building confusion

Johnson & Johnson: "Users felt confused on who was added and when," with "no way to vet the invites or request to join."

Team components with roles + invite + chat
No live status when tied to a Hackathon

A Project Room created via an Initiative was linked only through a nav item — no information passed between them.

Initiative Status component
Prototyping

An AI rapid design process

Scope, prototype first, refine later — the meta-value was proving the workflow as much as the feature. Claude Chat (research & explore) → Claude Design (prototype + refine + test) → Claude Code (production).

"Much more got done in this 30 than a typical 100."

Brightidea front-end developer

Originally scoped for 150 story points by engineering, the redesign went to production in only 30 thanks to the new AI process — and completed both backend and frontend within the same sprint.

The Solution

All in one place for a team to collaborate

1 Project Information

Editable hero image, project name, member count, and description.

2 Quick Actions bar

Quick creation of key objects: Whiteboard · Memo · View Tasks · Files.

3 "Most Recent" items

Memos & whiteboards at a glance, timestamped, with direct Open links.

4 Activity + History feed

Real-time log of activity, uploads, task completions, and whiteboard updates.

5 Team sidebar + chat

Avatars, names & roles always visible, an Add button, and real-time team chat.

6 Initiative Templates

App-based reusable components that give users valuable data and info.

Sequencing

Deliberate slicing — Now · Next · Later

Front-end-first slices kept demos unblocked while complex backend work (chat, history) caught up separately — sequencing, not scope creep.

Outcomes

Outcomes & reflection

  • Shipped a ground-up redesign as a safe, toggle-gated slice — without disrupting a single existing room.
  • Grounded every design decision in converging evidence: customer UX diagnoses, dogfood bugs, and an internal audit.
  • Built a production-ready experience focused on true participant UI/UX — a real team collaboration tool.
  • Designed and built a shared, componentized UI so apps could scale on a common foundation.
  • Validated an AI rapid design process — and learned to separate "AI process tax" from real engineering effort.
